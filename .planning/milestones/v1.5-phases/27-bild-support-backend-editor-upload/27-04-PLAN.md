<objective>
Extend the EXISTING WYSIWYG contenteditable component (Phase 24/26) so the Vorstand can insert inline images via a toolbar button (file picker) OR drag&drop onto the editor. This is an INCREMENTAL extension of the shared component — component-first, NO inline-RSX duplication, reusing the existing `exec_command_str("insertHTML", …)` facade, the toolbar button-clone pattern (with the mandatory `onmousedown` selection-preserve invariant), and the existing FormData upload flow.

Purpose: The authoring half of image support (IMG-03). It relies on 27-01's POST /api/mail/assets + GET /api/mail/assets/{id}/bytes.
Output: A new `upload_mail_asset` API client fn, an image toolbar button, drag&drop handlers on the editor, i18n keys, and (per the always-test rule) a source-invariant grep-gate covering the new button's onmousedown invariant plus a unit test of the inserted-HTML shape.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user file → browser FormData → POST /api/mail/assets | the file bytes leave the browser toward the (admin-gated, MIME-sniffing) backend from 27-01; the frontend performs no trusted validation |
| inserted <img> → contenteditable DOM → stored body_html | the editor writes data-genossi-asset-id + a /bytes src; on store the src is stripped by 27-02's sanitizer (only data-genossi-asset-id persists) |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-27-16 | Tampering | client-side MIME/type trust | medium | mitigate | The frontend `accept=` filter and any client type check are UX hints only; authoritative PNG/JPEG/GIF + 5 MB validation is server-side (27-01 magic-byte sniff + body limit) — the frontend never gates security |
| T-27-17 | Info disclosure | preview /bytes src persisted as resolvable URL | low | mitigate | The `src="/api/mail/assets/{id}/bytes"` is convenience for the live editor only; 27-02's sanitizer strips it on store so only `data-genossi-asset-id` is persisted (no stored resolvable src) |
| T-27-18 | Availability | drop handler swallowing non-image drops / breaking paste | low | mitigate | ondrop only handles image files and mirrors the proven onpaste preventDefault-first pattern; a grep-gate asserts prevent_default presence |
| T-27-SC | Tampering | npm/cargo installs | high | mitigate | No new crates; only additive `web-sys` features (DragEvent/DataTransfer) already vendored with web-sys — no package install; if any install appears, add a blocking-human checkpoint |
</threat_model>
