<objective>
Build the three Service-layer primitives that Plans 03 and 04 will consume: (1) `sanitize_html` — the ammonia-backed shared sanitizer called at every author-HTML store-side entry point; (2) `html_env()` + `render_html_template()` + `format_de()` — the autoescaping minijinja env used to render `body_html`, plus the FMT-01 German date helper wired into the shared context builder; (3) `RenderedContent { subject, body, body_html }` — the new return shape of `resolve_rendered_content` that carries the rendered HTML from the render layer to the worker (Plan 04) and to `build_message` (Plan 03).

Purpose: These three primitives are the seams the phase needs. Building them together (rather than one per plan) keeps the diff coherent — the render layer's new struct depends on the new html_env, which depends on the new dependency, which is used by the new sanitize module. Wiring them into services + REST is the next plan (04); MIME assembly is Plan 03.

Output: One new module (`sanitize.rs`), two extended modules (`template.rs`, `render.rs`), one Cargo.toml edit, one lib.rs mod declaration. No REST changes. No MIME changes. No worker changes. All prior text-mail and repayment-context render paths unchanged.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Author-HTML → sanitize_html → persistence | Untrusted author HTML crosses this seam in Plan 04. This plan only builds the sanitizer helper. |
| Member value → html_env autoescape → HTML body | Untrusted member data (`first_name`, `company`, …) crosses this seam whenever a Vorstand template renders. Autoescape neutralizes reserved chars (`<`, `>`, `&`, `"`, `'`). |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-23-03 | Tampering | HTML rendering of member values (`{{ first_name }}` etc.) | high | mitigate | `html_env()` sets `AutoEscape::Html` — `<script>&Co` in a member value renders as `&lt;script&gt;&amp;Co`. Unit test `html_env_autoescapes_member_value` pins the behavior. Existing `strict_env` untouched for text bodies (regression test `strict_env_does_not_escape_member_value`). Aligned with ASVS V5 (Input Validation & Output Encoding). |
| T-23-04 | Tampering | Author-HTML → persistence pathway | high | mitigate | `sanitize_html(&str) -> String` wraps `ammonia::clean()` with permissive default (D-01). Strips `<script>`, event handlers, `javascript:`/`data:` URL schemes; auto-adds `rel="noopener noreferrer"`. Four unit tests cover the four attack surfaces. Wiring happens in Plan 04 at 4 entry points (D-03). |
| T-23-05 | Tampering | Jinja placeholder inside HTML attribute (RESEARCH Pitfall 1) | medium | mitigate | Sanitize test `sanitize_preserves_jinja_placeholder_in_text_content` proves placeholders in text content survive. Attribute placeholders are OUT OF SCOPE — the Phase-24 editor never emits them; author templates that violate this contract will have the offending attribute stripped by ammonia, failing loudly at store time. Documented in Plan 04's contract. |
