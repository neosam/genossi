<objective>
Create the operator-facing runbook required by MAIL-04 (D-12): a documented, ONE-SHOT verification step that the prod SMTP relay advertises `8BITMIME` before an operator flips `smtp_encoding` to `8bit`. This is verify-in-prod by design — the dev environment cannot reach the prod relay (network isolation, per CONTEXT and RESEARCH). Documenting the check is the deliverable; performing it lives with the operator.

Purpose: MAIL-04 is not code — it is a policy + procedure. Without this doc, an operator flipping `smtp_encoding=8bit` against a non-8BITMIME relay risks `550` bounces or silent byte mangling (RFC 6152, RESEARCH § Pitfall 2). This plan is independent of Plans 01/02 — different file, no code dependency — so it runs in Wave 1 in parallel.

Output:
- New file `docs/OPERATIONS.md` with a top-level `# Operations Runbook` header and a `## SMTP-Encoding umschalten (MAIL-04)` section.
- The section contains: rationale (why 8BITMIME must be verified), the `openssl s_client` command to run, the expected `250-8BITMIME` line, the exact config-key toggle, and the rollback path.
</objective>
