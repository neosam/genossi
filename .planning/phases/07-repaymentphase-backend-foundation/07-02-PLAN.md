| Boundary | Description |
|----------|-------------|
| DAO-Layer ↔ SQLite | sqlx-parameterisierte Queries; KEINE String-Konkatenation in SQL |
| Concurrent Service-Calls | Optimistic Locking via `version`-UUID; Race-Detection auf DB-Ebene via `rows_affected == 0` |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-02-01 | Tampering | SQL-Injection in `dump_all`/`create`/`update` | mitigate | Alle Queries verwenden `sqlx::query`/`sqlx::query_as` mit `.bind(...)` — KEIN `format!`-konstruiertes SQL. Pattern 1:1 wie assembly.rs. Grep-Gate im acceptance_criteria von Plan 03 falls dort relevante Service-Builds Variable-Interpolation einfügen — hier nicht relevant. |
| T-07-02-02 | Tampering | Concurrent Update überschreibt fremde Änderung | mitigate | UPDATE-WHERE-Klausel enthält `AND version = ?` + `rows_affected == 0`-Check → `DaoError::ConflictError("Version mismatch")`. Test 2 verifiziert. |
| T-07-02-03 | Repudiation | Update auf soft-gelöschte Row geht durch | mitigate | UPDATE-WHERE-Klausel enthält `AND deleted IS NULL`. Soft-gelöschte Rows sind für nachfolgende Updates unsichtbar (Ausnahme: der Delete-Übergang selbst, der die Row im selben tx auf `deleted = now()` setzt — Pre-Exists-Check trifft die Pre-Delete-Row, dann setzt UPDATE den Delete; siehe assembly.rs-Pattern). |
| T-07-02-04 | Information Disclosure | `dump_all` exponiert soft-gelöschte Phasen | accept | `dump_all` ist explizit "alles raus inkl. deleted" (für Audit-Tooling). Service-Layer-API (`all()`) filtert per Default-Impl im Trait → REST-Endpoint sieht nur aktive Phasen (D-10). Direkter `dump_all`-Aufruf ist nur intern (Audit/Migration), keine REST-Exposition. |
| T-07-02-05 | Tampering | `i32::try_from(db.fiscal_year)` panics statt error | mitigate | Konvertierung läuft via `try_from(...).map_err(|e| DaoError::ParseError(...))` — KEIN `as i32`-Cast, der overflowt. Korrupte DB-Werte (z.B. 999999) → kontrollierter ParseError statt Panic. |
