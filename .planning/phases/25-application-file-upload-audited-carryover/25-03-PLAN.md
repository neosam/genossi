<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| REST → Service | Multipart bytes + `application_id` from HTTP cross this boundary. Service enforces `MAX_FILE_SIZE`, application-exists, permission, and single-slot invariant. |
| Service → DAO | Entities passed by value; DAO trusts them. |
| Service → DocumentStorage | Filesystem writes with `relative_path` computed by the Service (UUID-based, never client-controlled). |
| Unauthenticated → Service | Unauthenticated callers MUST bounce off `check_permission` BEFORE any DAO or storage side-effect (APDOC-02 = CR-02). |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-25-03-01 | Information Disclosure | CR-02 permission-check ordering | high | mitigate | `check_permission` FIRST, `current_user_id` AFTER in every method. Enforced by acceptance-grep awk gate + 6th unit test (Test 3) that fails if DAO/storage mocks are touched on unauthorized call. |
| T-25-03-02 | Denial of Service | Oversized upload | high | mitigate | Service enforces `MAX_FILE_SIZE = 50 * 1024 * 1024` before any storage.save; REST layer will additionally set `DefaultBodyLimit` in Wave 3 (defense in depth). |
| T-25-03-03 | Tampering | Client MIME spoofing | high | mitigate | Client MIME is discarded at the REST layer (Wave 3) via `lookup_allowed_mime`. Service receives server-derived MIME only. Service does NOT re-derive from data bytes (accepts REST layer as trusted for MIME extraction). |
| T-25-03-04 | Tampering | Single-slot invariant bypass | high | mitigate | Service `upload()` uses `find_active_by_application_id` → branch (create OR update). DB partial unique index (Wave 1) catches any regression. Test 2 pins the replace-in-place code path. |
| T-25-03-05 | Elevation of Privilege | Replay of stale entity | medium | mitigate | Optimistic locking via `version` UUID in DAO update; Service does not manually check but relies on DAO’s `ConflictError` return. |
| T-25-03-06 | Tampering | Path traversal in storage layout | low | mitigate | `relative_path` uses only UUIDs (`applications/{app_id}/{doc_id}.{ext}`) — no client-controlled path components. `FilesystemDocumentStorage` additionally enforces `path_clean` + `starts_with(base_path)`. |
| T-25-03-07 | Information Disclosure | Orphan file after commit failure | low | accept | Save-new happens BEFORE DAO update; if update fails and tx rolls back, orphan file remains at `new_relative_path`. Documented in deferred housekeeping-job (CONTEXT.md `<deferred>`). Acceptable because file is UUID-named and inaccessible via any API. |
| T-25-03-SC | Tampering | package installs | low | accept | No new packages installed in this plan. All deps (async-trait, mockall, tracing, time, uuid) already in Cargo.lock. |
</threat_model>
