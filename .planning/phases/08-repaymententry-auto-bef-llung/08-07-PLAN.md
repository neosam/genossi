    Ersetze den `audited_update!`-Block + commit + Return (Z. 254-267) durch:

    ```rust
            // audited via macro (Audit-Disziplin T-08-03-01)
            crate::audited_update!(
                self,
                self.repayment_entry_dao,
                id,
                &entity,
                REPAYMENT_ENTRY_PROCESS_UPDATE,
                &user_id,
                tx
            );

            // CR-01 Fix: Re-read to get the new version UUID generated by the DAO.
            // Pattern mirrors MemberServiceImpl::update (member.rs:343-348).
            // The DAO writes a fresh version via `Uuid::new_v4()` on every UPDATE
            // (repayment_entry.rs:136); without this re-read the Service returns
            // the pre-update entity, leaving the client with a stale version that
            // produces 409 on every follow-up PUT.
            let refreshed = self
                .repayment_entry_dao
                .find_by_id(id, tx.clone())
                .await?
                .ok_or(ServiceError::EntityNotFound(id))?;

            self.transaction_dao.commit(tx).await?;
            Ok(RepaymentEntry::from(&refreshed))
        }
    ```

    **Schritt 2 — Fix `batch_toggle_status` (Z. 355-449), Loop-Body (Z. 411-445):**

    Ersetze den Loop-Body so, dass nach `audited_update!` ein Re-Read der jeweiligen Entry erfolgt und DAS in `updated` gepusht wird:

    ```rust
            for (idx, entry_id) in input.entry_ids.iter().enumerate() {
                let mut entity = self
                    .repayment_entry_dao
                    .find_by_id(*entry_id, tx.clone())
                    .await?
                    .ok_or_else(|| conflict_body(idx, *entry_id, "entry not found"))?;

                // Source-Status muss Open oder Contacted sein
                if !matches!(
                    entity.status,
                    RepaymentEntryStatus::Open | RepaymentEntryStatus::Contacted
                ) {
                    return Err(conflict_body(
                        idx,
                        *entry_id,
                        &format!(
                            "source status is '{}', expected Open or Contacted",
                            entity.status.as_str()
                        ),
                    ));
                }

                entity.status = input.target_status.clone();
                // audited via macro (Audit-Disziplin T-08-03-01)
                crate::audited_update!(
                    self,
                    self.repayment_entry_dao,
                    *entry_id,
                    &entity,
                    REPAYMENT_ENTRY_PROCESS_BATCH_TOGGLE,
                    &user_id,
                    tx
                );

                // CR-01 / WR-01 Fix: Re-read after audited_update! to pick up the
                // new version UUID generated by the DAO. Without this refresh the
                // returned Vec carries N stale versions (one per entry).
                let refreshed = self
                    .repayment_entry_dao
                    .find_by_id(*entry_id, tx.clone())
                    .await?
                    .ok_or(ServiceError::EntityNotFound(*entry_id))?;
                updated.push(RepaymentEntry::from(&refreshed));
            }
    ```

    Hinweis: Hier wird `ServiceError::EntityNotFound` verwendet (nicht `conflict_body`), weil die Entry GERADE eben in dieser Tx geupdated wurde — wenn der Re-Read jetzt None liefert, ist das ein interner Konsistenzfehler, kein User-Error.
