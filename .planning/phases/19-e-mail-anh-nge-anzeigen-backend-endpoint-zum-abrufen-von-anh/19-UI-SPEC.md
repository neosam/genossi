# Phase 19 — UI Design Contract

> Visual and interaction contract for the frontend portion of Phase 19
> (E-Mail-Anhänge anzeigen). Generated by gsd-ui-researcher, consumed by
> planner, executor, ui-checker, and ui-auditor.

Scope: NEW components `InboxAttachmentList` + `InboxAttachmentListItem` under
`genossi-frontend/src/component/inbox/`, plus the Detail-Pane section in
`genossi-frontend/src/page/inbox_page.rs` (replaces the existing
"nicht anzeigbar im MVP"-Hinweis at `inbox_page.rs:331-335`).

Hard-locked upstream decisions from
`.planning/phases/19-.../19-CONTEXT.md` (D-01 through D-14) drive this
contract. Backend / persistence / endpoint design are out of scope here.

## Design System

| Property          | Value                                                                                  |
|-------------------|----------------------------------------------------------------------------------------|
| Tool              | none (manual Tailwind utility classes — project convention)                            |
| Preset            | not applicable                                                                         |
| Component library | Dioxus 0.6 components (`genossi-frontend/src/component/`)                              |
| Icon library      | none — paperclip emoji `📎` (matches `mail_list_item.rs:36`) + Unicode glyphs           |
| Font              | Tailwind default (`font-sans` / system stack) — no project override                    |
| Locales           | `Locale::En` + `Locale::De` (the only two locales; see `i18n/mod.rs`, `genossi-frontend/CLAUDE.md`) |

**Detected design baseline** (from `mail_list_item.rs`, `status_badge.rs`,
`reply_form.rs`, current `inbox_page.rs:303-340`):

- Spacing: `p-2`, `p-3`, `gap-2`, `mt-2`, `mt-3`, `pt-2`, `pt-3` — multiples
  of 4px (Tailwind defaults). No custom scale tokens defined.
- Typography: `text-xs` (12px), `text-sm` (14px), `text-base` (16px),
  `text-lg` (18px). Weights: `font-medium` (500), `font-semibold` (600);
  plain body stays at default weight 400.
- Surface colors: white default, `bg-gray-50` for body `<pre>`, `bg-blue-50`
  for selection, `border` (gray-200) for panels. Status semantic colors:
  `text-green-600` (done), `text-purple-600` (replied), `text-gray-500`
  (archived/secondary text), `text-blue-600` (open / CTA links),
  `text-amber-700` (current attachment hint).
- Interactive primary color across the inbox page is `bg-blue-500` /
  `hover:bg-blue-600` for solid buttons (see reply form) and
  `text-blue-600 hover:underline` for ghost links (see back button).
- Destructive color: `text-red-600` (used elsewhere in inbox for delete
  links — kept consistent if any destructive action surfaces in this
  contract; none currently planned).

This contract STAYS WITHIN those tokens. No new color, no new spacing step,
no new font.

## Spacing Scale

Declared values (Tailwind defaults, multiples of 4):

| Token  | Value | Tailwind | Usage in Phase 19                                                                 |
|--------|-------|----------|-----------------------------------------------------------------------------------|
| xs     | 4px   | `gap-1`  | Inline icon→label gap inside an attachment row                                    |
| sm     | 8px   | `gap-2`  | Vertical rhythm inside `InboxAttachmentList` between header and item list         |
| md     | 12px  | `p-3`    | Internal padding of each `InboxAttachmentListItem` (matches mail list item rhythm) |
| md+    | 16px  | `gap-4`  | Horizontal gap between thumbnail and metadata column in image-preview rows        |
| lg     | 8px   | `pt-2`   | Top padding above the section divider (`border-t pt-2 mt-2`)                      |
| lg+    | 12px  | `mt-3`   | Top margin separating attachments section from preceding `<pre>` body             |

Exceptions: image-preview thumbnails use a fixed `max-h-24` (~96px) and
`max-w-32` (~128px) — these are not spacing tokens but element-size caps for
the inline preview (D-12). Touch targets for the download/preview buttons
sit at the standard Tailwind button height (`px-3 py-1.5` → ~32px tall);
on mobile (`md:` breakpoint not satisfied) the whole row stays tappable.

| Role            | Size   | Weight     | Line Height | Usage in Phase 19                                          |
|-----------------|--------|------------|-------------|------------------------------------------------------------|
| Body            | 14px   | 400        | 1.5         | Filename, "Vorschau" link label, oversized hint copy       |

## Color

60 / 30 / 10 split (re-uses existing inbox page palette — no new tokens):

| Role             | Value (Tailwind)             | Usage                                                                                  |
|------------------|------------------------------|----------------------------------------------------------------------------------------|
| Dominant (60%)   | `bg-white` (default surface) | Detail pane background, attachment row background                                      |
| Secondary (30%)  | `bg-gray-50` + `border` (gray-200) | Optional row hover (`hover:bg-gray-50`), section divider `border-t`               |
| Accent (10%)     | `text-blue-600` + `bg-blue-500` | "Herunterladen" download button, "Vorschau" link (PDF), filename hover affordance   |
| Destructive      | `text-red-600`               | Reserved — not used by Phase 19 (no destructive action surfaces in this contract)      |
| Warning hint     | `text-amber-700`             | Oversized hint copy, legacy-backfill hint copy ("Anhang nicht mehr verfügbar")         |

Accent reserved for:
1. Primary download button (`bg-blue-500 hover:bg-blue-600 text-white`) per row.
2. Secondary preview link `<a>` (PDF only) as ghost link `text-blue-600 hover:underline`.
3. Image preview thumbnail click affordance — the `<img>` itself wrapped in
   an `<a target="_blank">` pointing at the inline URL.

Accent is NOT used for the section header, the filename text, the size
label, or for the oversized/legacy hints. Warning copy uses `text-amber-700`
to match the current MVP hint style (consistency with `inbox_page.rs:331`).

## Copywriting Contract

All copy lives in the i18n enum (`i18n/mod.rs::Key`) with translations in
`de.rs` and `en.rs`. Five new keys are mandated by D-14 plus two
auxiliary keys (preview affordance + section-empty case).

| Element                       | i18n key                          | DE copy                                                                              | EN copy                                                                            |
|-------------------------------|-----------------------------------|--------------------------------------------------------------------------------------|------------------------------------------------------------------------------------|
| Section heading               | `InboxAttachmentsHeader`          | "Anhänge"                                                                            | "Attachments"                                                                      |
| Primary CTA per row           | `InboxAttachmentsDownload`        | "Herunterladen"                                                                      | "Download"                                                                         |
| Secondary CTA (PDF only)      | `InboxAttachmentsPreview`         | "Vorschau"                                                                           | "Preview"                                                                          |
| Empty / legacy backfill hint  | `InboxAttachmentsEmptyLegacy`     | "Anhang vor Phase 19 empfangen — bitte im Mail-Client öffnen"                        | "Attachment received before Phase 19 — open in your mail client"                   |
| Oversized hint                | `InboxAttachmentsOversized`       | "Zu groß ({size}) — bitte im Mail-Client öffnen"                                     | "Too large ({size}) — open in your mail client"                                    |
| Error state (download failed) | `InboxAttachmentsDownloadError`   | "Anhang konnte nicht geladen werden — bitte erneut versuchen"                        | "Could not load attachment — please try again"                                     |
| Accessibility label (image)   | `InboxAttachmentsImageAltPrefix`  | "Vorschau für {file_name}"                                                           | "Preview of {file_name}"                                                           |

Notes:
- Header renders as `"{header_text} ({n})"`, e.g. `Anhänge (3)`. The paperclip
  glyph `📎` is rendered statically before the header text (matches the
  inbox list `📎` style at `mail_list_item.rs:36`); it is NOT part of the
  i18n string so it stays language-neutral and aria-hidden.
- `{size}` is the same human-formatted size that appears in the row
  metadata (`12 KB` / `1.4 MB`) — see Formatting & States below.
- Destructive confirmation: NONE in this phase. Download and preview are
  non-destructive read actions; no delete/destructive flow is in scope.
- Empty state: if the detail TO carries `attachments: []` AND
  `has_attachments == false`, the whole section is NOT rendered at all
  (zero noise). The legacy hint copy is ONLY rendered when
  `attachments.is_empty() && has_attachments == true` (D-06).

## Component Contract

Two new components, both under `genossi-frontend/src/component/inbox/`,
both registered in `component/inbox/mod.rs` next to the existing
`InboxMailListItem`, `InboxReplyForm`, `InboxStatusBadge` exports.

### `InboxAttachmentList` — `attachment_list.rs`

| Concern    | Contract                                                                                       |
|------------|------------------------------------------------------------------------------------------------|
| Props      | `mail_id: String`, `attachments: Vec<InboxAttachmentView>`, `has_legacy_attachments: bool`     |
| Renders    | Section divider (`border-t pt-2 mt-3`), header row (`📎 {Anhänge} ({n})`), then either: a) iterates `InboxAttachmentListItem` rows, or b) renders the legacy-hint paragraph |
| Hides itself | When `attachments.is_empty() && !has_legacy_attachments`                                     |
| Position   | Inside the scrollable body column (`inbox_page.rs:344`), AFTER the `<pre>` body and BEFORE the assignment section divider |
| Replaces   | `inbox_page.rs:331-335` (the existing amber MVP hint) — that block is deleted as part of the wiring |
| Layout     | `div { class: "border-t pt-2 mt-3 flex flex-col gap-2" }` wrapping header `<div class="text-sm font-semibold">` + list `<ul class="flex flex-col gap-2">` or legacy `<div class="text-xs text-amber-700">` |

`InboxAttachmentView` is the frontend-local row model (define in
`src/state/inbox.rs` or alongside the component) carrying
`{ id: String, file_name: String, mime_type: String, size_bytes: u64, oversized: bool }`,
mirroring the TO fields from D-07.

### `InboxAttachmentListItem` — `attachment_list_item.rs`

| Concern  | Contract                                                                                                                                                              |
|----------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Props    | `mail_id: String`, `attachment: InboxAttachmentView`                                                                                                                  |
| Renders  | Single `<li>` row with consistent 12px internal padding (`p-3`), border (`border rounded`), white background (`bg-white`).                                            |
| Layout   | `flex items-center gap-3`: leading visual (icon or image thumbnail) → metadata column (`flex flex-col`) → trailing action column (`flex gap-2 ml-auto`).               |
| Leading visual | If `mime_type.starts_with("image/")` AND `!oversized` → `<img>` thumbnail (D-12). Otherwise → emoji glyph by MIME-family (see Glyph Table). All glyphs are aria-hidden. |
| Metadata | Line 1: filename (`text-sm`, truncate-on-overflow, full filename in `title` attribute). Line 2: `text-xs text-gray-500` showing formatted size + dot separator + short MIME label (`PDF`, `Bild`, `Word`, `Excel`, `Datei`). |
| Action column | See Action Matrix.                                                                                                                                              |
| Error visual | If download throws, the row swaps the button label to the `InboxAttachmentsDownloadError` copy for 4s, then resets. No global toast.                            |

#### Glyph Table (leading visual when no image preview)

| MIME family                                | Glyph |
|--------------------------------------------|-------|
| `application/pdf`                          | `📄`  |
| `image/*` (oversized → no thumbnail)       | `🖼️`  |
| `application/zip`, `application/x-tar`, `application/gzip` | `🗜️`  |
| `application/msword`, `application/vnd.openxmlformats-officedocument.wordprocessingml.*` | `📝` |
| `application/vnd.ms-excel`, `application/vnd.openxmlformats-officedocument.spreadsheetml.*` | `📊` |
| `text/*`                                   | `📃`  |
| anything else                              | `📎`  |

All glyphs are decorative — wrapped in `<span aria-hidden="true">`. The
filename + MIME label combination carries the semantic info for screen
readers.

#### Action Matrix (D-08, D-11, D-12)

| Case                                | Primary action                                              | Secondary action                                          | Tertiary visual                                                |
|-------------------------------------|-------------------------------------------------------------|-----------------------------------------------------------|-----------------------------------------------------------------|
| `oversized == true`                 | (none)                                                      | (none)                                                    | Inline label `InboxAttachmentsOversized` in `text-amber-700`     |
| `mime_type == "application/pdf"`    | `<a class="…bg-blue-500…">` `Herunterladen` (default disposition) | `<a class="text-blue-600 hover:underline" target="_blank">` `Vorschau` → inline disposition URL | none                                                            |
| `mime_type.starts_with("image/")`   | `<a class="…bg-blue-500…">` `Herunterladen` (default disposition) | (none — preview is the thumbnail itself, wrapped in `<a target="_blank">` to the inline URL) | Inline `<img>` thumbnail (`max-h-24 max-w-32 object-contain rounded border`) |
| any other MIME                      | `<a class="…bg-blue-500…">` `Herunterladen` (default disposition) | (none)                                                    | none                                                            |

Implementation notes:
- Primary action is rendered as `<a href="…">` with `download` attribute,
  NOT as a `<button>` — clicking a real anchor avoids the
  `feedback_dioxus_button_type.md` page-reload pitfall (no onclick +
  prevent_default needed). The browser handles the download natively from
  the backend's `Content-Disposition: attachment` header.
- Secondary "Vorschau" for PDFs is `<a target="_blank" rel="noopener">`
  pointing at the inline-disposition URL — browser renders PDF in-tab.
- Image thumbnail `<a>` wrapper has `target="_blank" rel="noopener"` for
  the "click to open large" behavior demanded by D-12.
- The thumbnail's `<img src>` points at the inline-disposition URL of the
  same attachment. No separate thumb endpoint exists (full-size download
  is acceptable for MVP — 10 MB hard cap from D-02 bounds the worst case).
- `<img>` carries `alt="{InboxAttachmentsImageAltPrefix} {file_name}"` and
  `loading="lazy"`.

## Formatting & States

### Size formatting

A reusable function (place in `src/util/format.rs` if it does not yet
exist, or co-locate in `component/inbox/attachment_list_item.rs`) maps
`size_bytes: u64` to a human-readable string. Contract:

| Range                  | Output format     | Examples              |
|------------------------|-------------------|------------------------|
| < 1024                 | `{n} B`           | `42 B`, `999 B`        |
| < 1024 × 1024          | `{n} KB`          | `12 KB`, `1023 KB`     |
| < 1024 × 1024 × 1024   | `{n.n} MB`        | `1.4 MB`, `9.8 MB`     |
| ≥ 1024 × 1024 × 1024   | `{n.n} GB`        | `1.2 GB`               |

- KB threshold uses integer division (no fractional KB).
- MB/GB use one decimal place via integer math (no `format!("{:.1}")`
  rounding surprises): compute `tenths = size * 10 / unit`, then
  `format!("{}.{} {}", tenths / 10, tenths % 10, unit_label)`.
- The same formatted string is interpolated into the
  `InboxAttachmentsOversized` `{size}` placeholder so the user sees a
  consistent representation between metadata line and warning copy.

### State transitions per row

| State                | Trigger                                                  | Visual                                                                                  |
|----------------------|----------------------------------------------------------|-----------------------------------------------------------------------------------------|
| Idle                 | Default                                                  | Solid blue download button + (PDF only) "Vorschau" link                                 |
| Hover (download)     | Pointer over button                                      | `hover:bg-blue-600` darkens primary                                                     |
| Hover (preview link) | Pointer over "Vorschau"                                  | `hover:underline`                                                                       |
| Oversized            | Attachment `oversized == true`                           | No primary/secondary action — only `InboxAttachmentsOversized` label in amber           |
| Error                | Anchor click → server returns non-2xx (rare; backend is read-only) | Inline label `InboxAttachmentsDownloadError` for 4s, then revert. NO global toast.    |
| Empty (legacy)       | `attachments.is_empty() && has_attachments == true`      | Section header still renders with count `(0)`; below the header a single amber paragraph with `InboxAttachmentsEmptyLegacy` copy |
| Hidden               | `attachments.is_empty() && has_attachments == false`     | The whole section is not rendered                                                       |

Loading state for the section itself is covered by the existing
`*detail_loading.read()` branch in `inbox_page.rs:316` — no per-section
spinner is introduced.

### Accessibility

- Section header is a `<div>` styled as `text-sm font-semibold` to avoid
  introducing a new `<h2>` mid-detail-pane (page heading hierarchy already
  uses `text-lg font-semibold` for subject at line 321). If the inbox
  page later upgrades to semantic headings, this contract upgrades the
  attachment header to `<h3>` in lock-step.
- Each `<li>` row is keyboard-focusable through its anchor children (no
  custom `tabindex`).
- Images carry `alt` text built from the `InboxAttachmentsImageAltPrefix`
  i18n key + filename.
- Decorative glyphs use `aria-hidden="true"`.
- Action labels are full words (`Herunterladen`, `Vorschau`) — no
  icon-only buttons that would need extra `aria-label`.

## Anti-Patterns (locked by upstream constraints)

| Forbidden                                                                                       | Reason                                                                                  |
|-------------------------------------------------------------------------------------------------|------------------------------------------------------------------------------------------|
| Inline RSX list of attachments inside `inbox_page.rs`                                           | Component-First-Prinzip — `feedback_component_first.md`, D-13                            |
| `<button onclick=…>` for download or preview without `r#type: "button"`                         | `feedback_dioxus_button_type.md` — page-reload bug. Use `<a>` anchors instead.            |
| New locale beyond De/En                                                                         | Project has exactly two locales (`i18n/mod.rs`, frontend CLAUDE.md)                      |
| New color outside the existing inbox palette (gray-50/100/500/600, blue-500/600, amber-700)     | Stay consistent with inbox page surface tokens                                           |
| MIME-icon library import (e.g. `lucide`)                                                        | No icon dependency in the project today — Unicode glyphs match the existing `📎` style    |
| Hardcoded copy (anything other than i18n-key lookup) for header / button / hint text            | D-14 mandates i18n keys                                                                  |
| Inline preview for `text/html` or `text/plain`                                                  | Deferred (CONTEXT `<deferred>`); only `image/*` and `application/pdf` get inline preview |
| Adding `aria-live` or toast notification for download success                                   | Non-event; native browser download UX is the success signal                              |
