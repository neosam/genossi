<objective>
Build the `mail_asset` entity across all backend layers (DAO trait, SQLite impl, service trait, service impl, REST handlers, TO, migration, DI wiring). This is the foundation for image inline-embedding: it persists uploaded images as inline SQLite BLOBs (NOT filesystem), enforces admin-only upload/read, and validates PNG/JPEG/GIF via magic-byte sniffing.

Purpose: Every downstream plan needs this entity — the send-path CID renderer (27-03) loads asset bytes by id, and the frontend editor (27-04) calls POST /api/mail/assets and references GET /api/mail/assets/{id}/bytes.
Output: A working, admin-gated upload + bytes-download surface with an in-memory-SQLite DAO round-trip test, a service mockall test suite including a CR-02 permission-first regression guard, and an e2e test for the /bytes endpoint.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser (Vorstand) → POST /api/mail/assets | untrusted multipart file bytes + client-supplied filename/Content-Type cross here |
| browser → GET /api/mail/assets/{id}/bytes | any authenticated caller could try to read arbitrary asset ids |
| REST handler → service | raw bytes handed to the service, which is the sole authz + validation choke-point |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-27-01 | Spoofing/Elevation | upload/download auth | high | mitigate | `check_permission("admin", …)` is the FIRST statement of every mail_asset service method (CR-02); regression-guard test asserts zero DAO calls on denial (IMG-02/IMG-04) |
| T-27-02 | Tampering | file upload (SVG/polyglot) | high | mitigate | Magic-byte MIME sniff accepts ONLY PNG/JPEG/GIF; SVG and polyglots rejected with 415; server-derived MIME stored, client Content-Type/extension ignored (IMG-05 intent) |
| T-27-03 | DoS | oversized upload | high | mitigate | `DefaultBodyLimit::max(5 MB)` at the route + a redundant service-side `size_bytes > 5 MB` ValidationError (defense-in-depth) |
| T-27-04 | Info disclosure | /bytes read of others' assets | medium | mitigate | /bytes is admin-gated in the service; there is no public path and no unauthenticated route (global forbid_unauthenticated layer + service admin check) |
| T-27-05 | Tampering | stored resolvable src | low | accept | Only bytes + metadata are stored; no URL is persisted. `src` is injected downstream (27-04 preview / 27-03 cid) — not this plan's surface |
| T-27-SC | Tampering | npm/pip/cargo installs | high | mitigate | No new packages installed this phase (RESEARCH Package Legitimacy Audit N/A); if any install appears in execution, add a blocking-human checkpoint before it |
</threat_model>
