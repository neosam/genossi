<objective>
Harden the `<img>` rule in `genossi_mail/src/sanitize.rs`: replace the permissive `ammonia::clean()` default (which today allows `<img src="https://…">`) with a custom `ammonia::Builder` that permits `<img>` only with the `data-genossi-asset-id` attribute, strips `src`/`data:`/external-http, and drops SVG. This is the store-boundary that guarantees only `data-genossi-asset-id` is persisted — `src` is injected downstream at preview/send time, never stored.

Purpose: Security choke-point for IMG-05. It also defines the `<img data-genossi-asset-id>` contract that the CID renderer (27-03) transforms and the editor (27-04) inserts.
Output: A tightened sanitizer with new round-trip tests (asset-id survives; src/data:/svg stripped) and all existing Phase 23/26 tests still green.
</objective>

- The `<img data-genossi-asset-id="X">` persisted-HTML contract (consumed by 27-03 render.rs::rewrite_img_cids and 27-04 editor insert).
