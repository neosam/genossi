<objective>
Add inline-image embedding to the send path: a pure `rewrite_img_cids` function (render.rs) that transforms `<img data-genossi-asset-id="X">` into `<img src="cid:asset-N@genossi">` and returns the referenced asset ids; an extended `build_message` (send.rs) that, when images are present, wraps the existing `multipart/alternative` in a `multipart/related` with lettre inline parts (matching Content-IDs); a 25 MB total-size guard on the base64-encoded wire size BEFORE assembly; and asset-byte loading in the worker + test-mail service. The no-image path stays byte-identical (IMG-09).

Purpose: This is the delivery half of image support (IMG-06/07/08/09). All send.rs changes live in this single plan to avoid intra-phase merge conflicts on that file.
Output: Working related-MIME assembly for image mails, an untouched no-image path, a base64 25 MB guard, and unit tests for the related structure + CID matching + the size guard — with every pre-existing send.rs test left unmodified and green.
</objective>
