# Phase 4 — UI Design Contract

> Visual and interaction contract for the Genossi GV-Anwesenheits-Erfassung frontend. Generated by gsd-ui-researcher (Component-First Dioxus + Tailwind), verified by gsd-ui-checker.

This contract is **prescriptive at the visual-state level** (states, classes, spacing, copy) and **leaves pixel-precise discretion** (e.g., exact `gap-N`, `p-N`) where the visual hierarchy is unambiguous and the executor can match neighbouring patterns. Every D-NN reference points to `04-CONTEXT.md`.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (no shadcn — Dioxus RSX + Tailwind utility classes inline) |
| Preset | not applicable |
| Component library | none (custom components in `genossi-frontend/src/component/`) |
| Icon library | Unicode glyphs (existing convention — `\u{2630}`, `\u{25BC}`, `\u{00D7}`); for QR/Camera/Spinner use single inline SVG strings (no new dependency) |
| Font | Tailwind default (system stack: `-apple-system`, `BlinkMacSystemFont`, `"Segoe UI"`, ...). Monospace for the manual-code input only: `font-mono` |
| CSS | Tailwind 3 utility classes (existing: `tailwind.config.js` extends with `missingColor`, `blockedColor`, `print:` and `screen:` raw screens already configured) |
| Locales | de (default for Helfer-Page per CONTEXT-Discretion), en — **only two locales exist** (`src/i18n/de.rs`, `src/i18n/en.rs`); `cs.rs` does NOT exist in this codebase, despite some upstream docs claiming three locales |

**No new design tokens.** Reuse existing palette and spacing conventions (`px-3 py-2`, `rounded-md`, `border-gray-300`, `focus:ring-2 focus:ring-blue-500`).

## Spacing Scale

The codebase uses Tailwind's default 4-px scale. Phase 4 uses these tokens (all multiples of 4):

| Token | Tailwind | Pixel | Usage |
|-------|----------|-------|-------|
| xs | `1` | 4px | Icon-text gap, badge inner padding |
| sm | `2` | 8px | Tight inline gaps (`gap-2`), badge horizontal `px-2` |
| md | `3`–`4` | 12–16px | Default form padding (`px-3 py-2`), card content `p-4` |
| lg | `6` | 24px | Card padding (`p-6`), section bottom (`mb-6`) |
| xl | `8` | 32px | Modal padding (`p-8`), page top spacing |
| 2xl | `12` | 48px | Major section breaks (`my-12`), QR-Card height target |

**Exceptions:**
- Toggle button minimum touch target on Helfer-Page: `min-h-[44px] min-w-[44px]` (iOS HIG / DSGVO-friendly fat-finger zone). Achieved via `py-3 px-4` on tablet/mobile.
- Print page: A4-portrait with `@page { margin: 16mm; }` — print scale, not screen scale.

## Typography

The codebase uses Tailwind defaults; Phase 4 declares 3 sizes plus 1 monospace specialty:

| Role | Tailwind | Approx px | Weight | Line Height | Usage |
|------|----------|-----------|--------|-------------|-------|
| Body | `text-sm` to `text-base` | 14–16px | `font-normal` (400) | `leading-normal` (1.5) | Default text in lists, forms, table rows |
| Label | `text-xs` | 12px | `font-medium` (500) | `leading-tight` (1.25) | Status badges, table headers, helper text |
| Heading | `text-xl` to `text-2xl` | 20–24px | `font-bold` (700) | `leading-tight` (1.2) | Page headings (`h1`), card titles (`h2`) |
| Display | `text-4xl` | ~36px | `font-bold` (700) | `leading-tight` (1.2) | LiveCounter "X von Y" — visually dominant on the Anwesenheits-Tab |
| Mono (specialty) | `font-mono text-2xl tracking-widest` | ~24px wide-spaced | `font-semibold` (600) | `leading-tight` | Manual-Code-Input value display + QR-Card printed code |

**Heading anchor:** existing convention is `h1.text-2xl.font-bold.mb-6` (see `base_components.rs::Header`); Phase 4 reuses it for all page-titles. Card titles are `h2.text-xl.font-semibold` (matches `collapsible_section.rs`).

## Color

Genossi uses the **default Tailwind palette** with no custom theme tokens beyond `missingColor` (amber-200) and `blockedColor` (red-300). Phase 4 introduces **no new tokens**; instead it composes from existing semantic-color conventions in `application_list.rs`, `error_alert.rs`, `timestamp_section.rs`, `base_components.rs`.

### 60 / 30 / 10 distribution

| Role | Tailwind | Hex | Usage |
|------|----------|-----|-------|
| Dominant (60%) | `bg-white` / `bg-gray-50` | `#ffffff` / `#f9fafb` | Page background, card surface, modal body |
| Secondary (30%) | `bg-gray-100` / `bg-gray-800` (TopBar) / `border-gray-300` | `#f3f4f6` / `#1f2937` | Card frames, borders, table-zebra, input borders, TopBar (vorstand only) |
| Accent (10%) | `bg-blue-600` / `text-blue-600` | `#2563eb` | **Reserved for**: primary CTAs only — see list below |
| Destructive | `bg-red-500` / `text-red-700` | `#ef4444` / `#b91c1c` | Destructive confirmations + error toasts only |

**Accent reserved for (explicit list — never apply blue-600 elsewhere):**

5. Active-tab indicator on assembly-details TabStrip

### Status-Badge palette (NEW for Phase 4 — Assembly-Status)

Reuse the **exact `bg-{color}-100 text-{color}-800 px-2 py-1 rounded text-xs font-medium`** pattern from `application_list.rs::status_badge_class`. Three status values get three distinct hues:

| Assembly Status | Tailwind Classes | Rationale |
|-----------------|------------------|-----------|
| `Preparation` (Vorbereitung) | `bg-gray-100 text-gray-800` | Neutral — not yet active |
| `Open` (Offen) | `bg-green-100 text-green-800` | Positive — currently running, mirrors `Bestaetigt` semantics |
| `Closed` (Geschlossen) | `bg-blue-100 text-blue-800` | Final — done, archival; **deliberately NOT red** (closing is the happy path, not a destructive event) |

### Helper-Token-Status palette (also NEW)

| Token Status | Tailwind Classes |
|--------------|------------------|
| `Open` (offen, druckbar) | `bg-yellow-100 text-yellow-800` (matches `StatusOffen` convention from applications) |
| `Used` (eingelöst) | `bg-green-100 text-green-800` |
| `Revoked` (widerrufen) | `bg-gray-100 text-gray-500` (subdued, no longer actionable) |

### Toggle-Button states (D-17/D-18, very prescriptive)

The Anwesend-Toggle is the most-clicked element on the Helfer-Page and the centerpiece of SC#6 (no Optimistic-UI). It MUST follow these exact classes:

| State | Tailwind Classes | Visible Glyph |
|-------|------------------|---------------|
| `idle / absent` (member is currently NOT marked present) | `bg-white border-2 border-gray-300 text-gray-700 hover:bg-gray-50` | empty box `\u{2610}` ("☐") |
| `idle / present` (member IS marked present, ready to be toggled off) | `bg-green-100 border-2 border-green-500 text-green-800 hover:bg-green-200` | filled checkmark `\u{2713}` ("✓") |
| `loading` (request in flight, regardless of source state) | `bg-gray-100 border-2 border-gray-300 text-gray-400 cursor-not-allowed` + `disabled` attribute + spinner glyph | spinner SVG (inline `<svg class="animate-spin h-4 w-4">`) |
| `error-flashback` (just-failed, brief 600ms shake) | adds `animate-pulse ring-2 ring-red-400` for 600ms via `setTimeout` then returns to previous idle state | unchanged glyph |

**Critical:** the executor MUST NOT add a "checked" visual to `loading` — Phase 4 SC#6 hard-constraint. The visual transitions ONLY on 200-OK from the request promise.

**Sizing:** square 44×44 minimum (`min-h-[44px] min-w-[44px] inline-flex items-center justify-center rounded-md`).

### Connection-Banner colors (D-16)

Sticky banner — appears at top of viewport when polling fails twice in a row. Vertically thin, horizontally full-bleed, dismissible only by reconnect (not by user click — would mask real outage).

| Aspect | Value |
|--------|-------|
| Background | `bg-amber-100` (NOT `bg-red-100` — banner is "warning, retrying", not "fatal error") |
| Text | `text-amber-900 text-sm font-medium` |
| Border | `border-b-2 border-amber-400` |
| Position | `sticky top-0 z-30 w-full px-4 py-2 print:hidden` |
| Layout | `flex items-center justify-between` — left: warning glyph + message; right: small spinner showing "trying" |
| Glyph | `\u{26A0}` ("⚠") |
| Print | `print:hidden` (must NOT appear in printed QR-Cards) |

The banner is rendered **inside `HelperShell` and inside the assembly-details Anwesenheits-Tab body** (NOT in `app.rs` global scope), so it scopes to pages that actually poll.

### Toast Notification position (D-17 errors)

Reuse the existing `members.rs::show_toast` mechanism (5s timeout). Position: **bottom-center on mobile, top-right on desktop**, identical to `members.rs` pattern.

| Aspect | Value |
|--------|-------|
| Container | `fixed z-40 bottom-4 left-1/2 -translate-x-1/2 md:bottom-auto md:left-auto md:top-4 md:right-4 md:translate-x-0 flex flex-col gap-2 max-w-md` |
| Single toast | `bg-red-600 text-white px-4 py-3 rounded-lg shadow-lg flex items-center gap-3` |
| Timeout | 5000ms (matches existing `members.rs::show_toast`) |
| Print | `print:hidden` |

### 2. `QrScanner` (`component/qr_scanner.rs`)

```rust
#[component]
pub fn QrScanner(
    on_scan: EventHandler<String>,    // raw scanned text — Helfer-Login parses URL or treats as code
    on_error: EventHandler<String>,    // German error message ready to display
    on_cancel: EventHandler<()>,       // user clicks the cancel/close X
) -> Element
```

**Visual states:**

| State | Layout |
|-------|--------|
| `idle` (before user click) | NOT rendered by this component — parent (`HelperLogin`) renders the trigger button. `QrScanner` is mounted only AFTER click. |
| `requesting permission` | Centered card: `bg-white rounded-lg p-6 max-w-sm` with text: "Kamera wird aktiviert…" + spinner |
| `streaming` | Black canvas: `relative bg-black aspect-square w-full max-w-md rounded-lg overflow-hidden`. Inside: `<video>` element fullsize. Overlay: corner-marker frame (`absolute inset-8 border-2 border-white rounded-lg`). Top-right close X: `absolute top-2 right-2 text-white text-2xl`. Bottom hint: `absolute bottom-3 left-0 right-0 text-center text-white text-sm`: "QR-Code im Rahmen positionieren" |
| `error / permission denied` | Centered card with `bg-red-50 border border-red-200 text-red-700 p-4 rounded-lg`. Single button "Manuell eingeben" returns to login form |

**Behavior contract:**
- On mount: `getUserMedia({video: {facingMode: 'environment'}})`. On success → start frame loop with BarcodeDetector or lazy-loaded ZXing-JS-Polyfill (D-01/D-02). On any failure → call `on_error` with the appropriate German message.
- On unmount: stop all MediaStream tracks (no permission-leak).
- On scan match: call `on_scan(text)`, then immediately stop tracks.

### 3. `ManualCodeInput` (`component/manual_code_input.rs`)

```rust
#[component]
pub fn ManualCodeInput(
    on_submit: EventHandler<String>,   // already validated 10-char Crockford-Base32
    submitting: bool,                  // disable input + show spinner during /api/helper/redeem
    error: Option<String>,             // localised German error (from on_submit failure)
) -> Element
```

**Visual:**

| Sub-element | Classes |
|-------------|---------|
| Container | `flex flex-col gap-3` |
| Label | `text-sm font-medium text-gray-700` — text: `HelperLoginManualHeading` |

### 5. `AttendanceList` (`component/attendance_list.rs`)

The shared list component used by BOTH Helfer-Page and Vorstand-Anwesenheits-Tab (Component-First D-11).

### 7. `LiveCounter` (`component/live_counter.rs`)

The most-watched element of the Anwesenheits-Tab. Hard-constraint: text must read literally "X von Y anwesend" (D-11 + ROADMAP SC#3).

```rust

    assembly_id: Uuid,
    polling_enabled: bool,                          // false when assembly Closed (Plan-discretion)
    on_connection_state: EventHandler<ConnState>,   // emits {Healthy, Warning, Lost} so HelperShell shows banner
) -> Element

pub enum ConnState { Healthy, Warning, Lost }  // Lost = >=2 consecutive failures
```

**Visual:**

| Sub-element | Classes |
|-------------|---------|
| Container | `bg-white border border-gray-200 rounded-lg p-6 mb-4 flex items-baseline justify-between` |
| Label-line (left) | `text-sm font-medium text-gray-500 uppercase tracking-wider` — text: "Anwesenheit" |
| Counter-line (right) | `text-4xl font-bold text-gray-900` — text: see state table below |

**State table (counter-line text — strict):**

| Polling state | Y known | X known | Text |
|---------------|---------|---------|------|
| Initial mount | no | no | `AttendanceCounterUnknown` ("Anwesenheit lädt…") |
| First poll OK | yes | yes | `AttendanceCounterLong` → e.g. "12 von 47 anwesend" |
| Poll fail (1× — Healthy still) | yes (cached) | yes (cached) | unchanged from last success |
| Poll fail (2×+ — Warning/Lost) | yes (cached) | dash | `AttendanceCounterLongLoading` → "— von 47 anwesend" |
| Poll recovery | yes | yes | back to current X |

**Why dash X but keep Y:** Y comes from the Member-Universe-Snapshot which is stable for the whole GV (Phase-1 Decision). Dashing Y would falsely imply "we don't know how many members exist" — Y stays. X is current attendance and IS unknown during outage — dash X.

**Polling behavior (D-14):**
- `use_resource` + `gloo_timers::future::TimeoutFuture::new(5_000).await`
- On every tick: GET `/api/assembly/{id}/stats`
- Track `consecutive_failures: u32`. Emit `Healthy` on success (reset to 0). Emit `Warning` on first failure. Emit `Lost` on second consecutive failure.
- Stop on unmount (Dioxus signal teardown).
