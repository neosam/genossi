<objective>
Add the additive `template_type TEXT NOT NULL DEFAULT 'member'` column to `mail_templates` and
thread it through every SQL/struct/entity/TO/service site (D-01, D-02, D-03), then seed the German
"Zahlungserinnerung" applicant template with fixed UUID `00000000-0000-0000-0000-000000000003`
(D-14). This creates the pool-separation data foundation for the applicant template type (D1 /
APTPL-01) and ships the ready-to-use reminder seed (APTPL-03). `template_type` is immutable after
create (Pitfall 3 option a).

Purpose: separate the applicant template pool from the member pool at the data layer so member
mass-mail never renders an application-only template, and deliver the reminder seed so the main
use-case needs zero manual configuration.
Output: 2 migrations + `template_type` on the entity/DB-row/TO/create-request/service path.

RESEARCH DRIFT RESOLVED (D-02): there is NO test DDL for `mail_templates` — unit tests never
`CREATE TABLE mail_templates`; e2e tests get the schema from real migrations. So the D-02
"inkl. Test-DDL" checklist reduces to the 8 production sites + the `MailTemplateDb` row struct.
Do not hunt for a test DDL to edit.
</objective>
