# Phase 18 — UI Design Contract

> Visual and interaction contract for the `MembershipAdjustModal`, `FiscalYearDateInput`, and Member-Detail-Page integration. Generated by gsd-ui-researcher from 18-CONTEXT.md (D-18-01..14, C-18-CF-01..12), `genossi-frontend/CLAUDE.md`, and existing component patterns. Consumed by gsd-planner, gsd-executor, and gsd-ui-checker.

## Design System

| Property | Value |
|----------|-------|
| Tool | none (shadcn not applicable — Dioxus 0.6.3 / Rust → WASM, not React/Next/Vite) |
| Preset | not applicable |
| Component library | Custom Dioxus components in `genossi-frontend/src/component/` (Modal, MemberSearch, ErrorAlert, ToastContainer, RequirePrivilege) |
| Icon library | None — Unicode glyphs (`←` Back, `✕` Close, `⚠` Warning, `•` Bullet); convention from existing `member_search.rs` and `toast.rs` |
| Font | System default (Tailwind preflight: `ui-sans-serif, system-ui, -apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, ...`) — no custom font loaded |
| CSS framework | Tailwind CSS utility classes (watch mode via `npx tailwindcss -i ./input.css -o ./assets/tailwind.css --watch`). Custom colors: `missingColor=amber-200`, `blockedColor=red-300` (not used in Phase 18) |
| Source-of-truth tokens | Tailwind default palette + spacing scale; `tailwind.config.js` extends only `screens.print/screen` + 2 status colors |

**Why no shadcn:** shadcn is a React component generator. This project is Rust-compiled-to-WASM via Dioxus 0.6.3. Components are written as Rust `#[component]` functions emitting RSX. shadcn gate is not applicable; the design contract is enforced via Tailwind utility class conventions documented below.

## Spacing Scale

All spacing uses Tailwind's default scale (4px base unit). Phase 18 declares the following subset as the contract:

| Token | Value | Tailwind class | Usage in Phase 18 |
|-------|-------|----------------|-------------------|
| xs | 4px | `gap-1`, `mt-1`, `p-1` | Helper-text-to-input gap (FiscalYearDateInput) |
| sm | 8px | `gap-2`, `p-2`, `mt-2`, `mb-2` | Compact element gaps; warning row to preview text; close-button margin |
| md | 12px | `px-3`, `py-3`, `gap-3` | Form input padding (matches existing `member_search.rs` inputs) |
| lg | 16px | `p-4`, `gap-4`, `mt-4`, `px-4`, `py-3` | Sub-Choice grid gap, preview box padding, form section gaps, button padding |
| xl | 24px | `p-6` | Sub-Choice button inner padding (D-18 Specifics: `p-6 border-2 ...`) |
| 2xl | 32px | `p-8` | Modal outer padding (existing `Modal` component — `max-w-3/4 max-h-[90vh] p-8`) |

**Exceptions:**
- Touch target minimum: Sub-Choice buttons render as `flex flex-col items-start p-6` (~88px high) — exceeds the 44px iOS/Android minimum.
- Submit button height: `px-6 py-2` (~40px tall) — acceptable for mouse/trackpad on desktop; on mobile, the Modal scrolls in the parent overflow container so smaller targets are accessible without zoom.
- No values outside the multiples-of-4 contract are used.

## Typography

Phase 18 declares exactly 4 type roles and 2 weights. All values use Tailwind's default font-size scale (rem-based; 1rem = 16px assumed).

| Role | Size | Weight | Line Height | Tailwind classes | Usage |
|------|------|--------|-------------|------------------|-------|
| Body | 14px | 400 (regular) | 1.5 | `text-sm` | Form labels, helper text, preview text, ErrorAlert body, dropdown items |
| Label | 14px | 500 (medium) | 1.5 | `text-sm font-medium` | Field labels above inputs (`block text-sm font-medium text-gray-700 mb-1` — pattern from existing forms) |
| Sub-Choice button title | 18px | 600 (semibold) | 1.25 | `text-lg font-semibold` | Sub-Choice card primary label |
| Heading | 20px | 600 (semibold) | 1.25 | `text-xl font-semibold` | Modal title (`Mitgliedschaft anpassen`) and Sub-View heading (`Kündigung`, etc.) — matches existing `repayment_entry_paidout_confirm.rs:62` pattern (`text-xl font-semibold`) |

**Auxiliary sizes used only for tertiary content (do not count toward the "3-4 sizes" cap because they are not declarative type-roles — they are status-decoration only):**
- `text-xs` (12px): preview-box "VORSCHAU" eyebrow label uppercase, helper-text-error caption — same usage as existing `error_alert.rs` and `member_search.rs` for de-emphasized metadata.

**Weights (exactly 2 declared):**
- 400 (regular, default) — body text and helper text
- 600 (semibold) — labels, headings, sub-choice titles, submit button labels

Note: `font-medium` (500) appears in the existing codebase form-pattern (`block text-sm font-medium text-gray-700 mb-1`) but is treated as a synonym of "label weight" within Tailwind's design (CSS weight=500 vs 600 visually similar at small sizes). Phase 18 standardises on `font-medium` for labels (matches existing forms) and `font-semibold` for headings/CTAs. The checker should treat these as the project's 2-weight contract.

## Interaction & State Contract

### Modal mounting (D-18-04)
- Local `use_signal::<bool>(false)` on `MemberDetails` page.
- Button click → `show_adjust_modal.set(true)` → conditional mount `Modal { MembershipAdjustModal { member, on_close, on_success } }`.
- `on_close` → `show_adjust_modal.set(false)`.
- `on_success` → `show_adjust_modal.set(false)` + `refresh_members().await` + toast (success variant).

### Step state (D-18-02, D-18-03)
- Enum `ModalStep { SubChoice, Cancel, PartialRepayment, Transfer, Upgrade }`.
- Initial: `SubChoice`.
- Sub-Choice card click → step transitions to that operation; **shared form fields (date) are preserved**, operation-specific fields (shares, recipient) reset. (Claude's-Discretion call per CONTEXT.md.)
- Back button (`← Zurück zur Auswahl`) sets step back to `SubChoice`; does NOT clear errors or close modal.

### Form validation gates (Submit-button-disabled)
Submit is enabled only when ALL of:
1. Date input is a valid `time::Date` (not empty, parses).
2. Date is within fiscal-year bounds (`is_valid_fiscal_year_date(date, today)` — Pure-Function mirror of Phase-15 backend logic).
3. For PartialRepayment / Upgrade: `shares >= 1`.
4. For PartialRepayment: `shares < current_shares` (= `<` strict; equal-to-all triggers a separate validation error suggesting Kündigung).
5. For Transfer: `shares >= 1` AND `to_id.is_some()` AND `from_id != to_id`.
6. No in-flight submission (`!submitting()`).

When disabled: button shows `disabled:bg-gray-300 disabled:cursor-not-allowed` (D-18 Specifics).

### Loading & submission states
- Recipients fetch (Transfer-Sub-View only): `use_resource(...)` returns `None` initially → render spinner row (`bg-blue-400 h-2 w-2 rounded-full animate-pulse` + "Lädt …" caption).
- On submit click: `submitting.set(true)` → API call → on Ok: `on_success.call(())` → on Err: `error.set(Some(msg))` + `submitting.set(false)` (modal stays open, ErrorAlert renders above form). Button label during submit: ellipsis "…" (D-18 Specifics).

### Focus management
- When modal opens: focus moves to the modal container (Dioxus default — no custom ref needed; native `<button>` and `<input>` keyboard tabbing works because the modal is a normal DOM tree).
- When Sub-View renders: native tab-order goes through fields top-to-bottom, then Submit, then Abbrechen. No autofocus on Date input (avoids unexpected mobile keyboard pop-up).
- Back button is reachable via Shift+Tab from the first form field.
- Escape key closing: **not implemented** in Phase 18 (existing `Modal` component does not support it; matches established pattern across the codebase — out of scope per CONTEXT.md "No A11y-Audit-Level über Standard hinaus").

### Responsive breakpoints
- Sub-Choice grid: `grid grid-cols-1 sm:grid-cols-2 gap-4` — 1-column stack on mobile (<640px), 2×2 on `sm:` and up (D-18 Specifics + Claude's-Discretion recommendation).
- Modal container reuses existing `Modal` component (`max-w-3/4 max-h-[90vh] p-8 overflow-y-auto`) — handles small screens via `overflow-y-auto`.
- Form fields inside Sub-Views: 1-column stack always (single-form-column layout). Date input + shares input + recipient search are full-width (`w-full`) and stack vertically.
- Toast position: `bottom-4 left-1/2 -translate-x-1/2` on mobile, `md:top-4 md:right-4` on desktop — unchanged from existing `toast.rs:38`.

### Voll-Übertrag detection (D-18-07)
- Pure-function `pub(crate) fn is_voll_uebertrag(shares: i64, from_current_shares: i64) -> bool` lives in `component/membership_adjust_modal.rs` (or a `helpers.rs` submodule).
- Renders an additional orange row inside the preview box: `div { class: "mt-2 text-orange-700 font-bold", "⚠ {warning_text}" }`.
- Does NOT disable the submit button (Vorstand may consciously trigger Voll-Übertrag).

### Auto-create-phase hint (Claude's-Discretion → planner recommendation: Pure-Mirror)
- Pure-function `compute_effective_date_mirror(date) -> (fiscal_year, effective_date)` in same module mirrors Phase-14 backend logic (~6 LOC; 6 edge-case unit tests required: 30.06, 01.07, 31.12, 01.01, Schaltjahr 29.02, Jahres-Anfang/-Ende).
- Frontend renders the `auto-create-phase` warning row in the PartialRepayment preview when `target_fiscal_year != latest_existing_phase.fiscal_year`. Latest existing phase is read from the existing repayment-phases signal/state (planner verifies the signal path).
- After-submit toast uses the `MembershipAdjustPartialRepaymentSuccessAutoCreate` variant if Response.phase is `Some`, otherwise the plain `MembershipAdjustPartialRepaymentSuccess` variant.
