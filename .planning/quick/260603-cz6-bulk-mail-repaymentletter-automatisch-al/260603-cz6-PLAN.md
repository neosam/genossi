# Quick Task 260603-cz6 — Bulk-Mail Auto-Attach RepaymentLetter

## Objective

Bulk-Mail-Versand mit persönlichem RepaymentLetter ermöglichen. Pro Empfänger wird sein zur referenzierten `repayment_phase_id` passendes `MemberDocument` (DocumentType=RepaymentLetter) automatisch vom Worker aufgelöst und als per-Empfänger-Attachment angehängt — analog zum bestehenden D-03-Context-Merge-Pattern.

## Design Decisions (USER-DECIDED)

| Frage | Entscheidung |
|-------|--------------|
| Trigger | Opt-in via neues Flag `attach_repayment_letter: bool` |
| 0 RepaymentLetters für Empfänger | Recipient als `failed` markieren mit `error="no_repayment_letter"` |
| >1 RepaymentLetters für Empfänger | Neuesten nehmen (`created DESC`), `tracing::warn!` loggen |
| Auflösung wo? | Worker (analog D-03-Context-Merge) — in-memory, kein DB-Persist der Attachments |

## Architecture

### Linkage RepaymentLetter ↔ Phase (etabliertes Pattern)

`MemberDocumentEntity` hat **kein** `phase_id`-Feld. Die Verbindung läuft über `description = "Anschreiben Auszahlung GJ {fiscal_year}"` — siehe Phase 13 D-LETT-04 (`genossi_service_impl/src/repayment_letter.rs:192`, `find_existing_letter_for_phase`).

**Wichtige Konsequenz:** zwei RepaymentPhases im gleichen `fiscal_year` würden bei Letter-Lookup kollidieren. Diese Limitation existiert bereits in der Letter-Generierungs-Logik (Phase 13) und wird hier 1:1 übernommen — kein neuer Mismatch, dokumentierter Trade-off.

### Worker-Pfad (analog D-03)

Im Worker-`process_recipient`-Loop (`genossi_mail/src/worker.rs`):

1. **Trigger-Check**: `job.attach_repayment_letter == true && job.repayment_phase_id.is_some()`
2. **Phase laden**: `repayment_phase_dao.find_by_id(phase_id)` → `fiscal_year`
3. **MemberDocuments laden**: `member_document_dao.find_by_member_id(member_id)` (existiert bereits, Worker-Dep ✓)
4. **Filter**:
   - `deleted IS NULL`
   - `document_type == DocumentType::RepaymentLetter`
   - `description == "Anschreiben Auszahlung GJ {fiscal_year}"`
5. **Anzahl-Branching**:
   - **0** → `mark_recipient_failed(recipient, "no_repayment_letter")`, skip mail-send, continue loop
   - **1** → `MailRecipientAttachment` in-memory zur `attachments`-Vec hinzufügen
   - **>1** → `sort_by(created DESC)`, `warn!` loggen, neuesten nehmen → wie 1
6. **File-Loading**: Über das vorhandene `document_storage` + send-pipeline (in `send_mail_for_recipient`, das bereits `relative_path` aus `MailRecipientAttachment` auflöst).

### Datenfluss `attach_repayment_letter`

```
SendBulkMailRequest (REST) 
  → MailService::create_job(..., attach_repayment_letter)
  → MailJob.attach_repayment_letter (DB column)
  → Worker liest job.attach_repayment_letter
  → Auto-Resolve-Pfad
```

`attach_repayment_letter` ist **persistiert** im `MailJob`, damit:
- Re-Tries funktionieren (kein Verlust der Konfiguration)
- Audit nachvollziehbar bleibt: "Dieser Job hat versucht, Briefe anzuhängen"
- Worker-Restart sicher ist

## Validation

REST-Handler (`send_bulk_mail`):

```rust
if body.attach_repayment_letter.unwrap_or(false) && body.repayment_phase_id.is_none() {
    return 400 BadRequest("attach_repayment_letter requires repayment_phase_id");
}
```

## Out of Scope (deferred)

- **Frontend-UI** für `attach_repayment_letter`-Toggle in `mail_page.rs` — separates Quick. Backend-API kann via Swagger getestet werden.
- **Phase-Spezifischer Lookup** via echter `phase_id`-Foreign-Key in MemberDocument — würde Migration + Letter-Generation umstellen, zu groß für diesen Quick.
- **Bulk-PDF-Bundle als gemerged Attachment** — User entschied: pro Empfänger einzelner Brief (analog Single-Send).
- **Auto-Mark als 'angeschrieben'** der RepaymentEntries nach Mail-Versand — separate Geschäftslogik (Frontend-Toast verweist bereits darauf).

## Acceptance / must_haves

1. `MailJob.attach_repayment_letter` ist persistiert (Migration + Entity + DAO).
2. `SendBulkMailRequest.attach_repayment_letter` deserialisiert mit `serde(default)`; Backward-Compat ohne Feld → false.
3. REST validiert: `attach_repayment_letter=true && repayment_phase_id=None` → 400 BadRequest.
4. Worker resolved pro Empfänger korrekt das passende RepaymentLetter-MemberDocument.
5. 0 Letters → Recipient `failed`, `error="no_repayment_letter"`.
6. >1 Letters → Newest, Warning-Log.
7. `cargo test --workspace` grün.
8. `cargo clippy --workspace --all-targets` clean.
