<objective>
Optionales Feld `account_holder` (Kontoinhaber) am Member hinzufügen. Editierbar auf der Detail-Seite. Im Auszahlungs-Anschreiben-PDF wird der Kontoinhaber als Briefadressat/Anrede-Name verwendet wenn gesetzt — sonst fällt es auf den normalen Mitgliedsnamen (`title + first_name + last_name`) zurück.

Purpose: Vorstand braucht den Fall, dass die Bankverbindung auf einen anderen Namen läuft (Ehepartner, Firma, Verstorbenenkonto). Der Brief muss dann den Konto-Inhaber adressieren, damit die Überweisung korrekt zugeordnet wird.

Output: 1 Migration + erweitertes Entity/DAO/Service/TO + Frontend-Input + Typst-Template-Fallback + Tests.

Scope-Exklusion (Planner-Discretion): `auszahlungsliste.typ` wird NICHT angepasst. Die Liste rendert eine `name`-Spalte, die in `pdf_generation.rs::build_repayment_list_inputs` (Pfad: ca. Z. 970-1000) aus `member.first_name + last_name` zusammengesetzt wird — die User-Description sagt explizit "im PDF für Rückzahlungen" (Anschreiben), nicht "in der Auszahlungsliste". Optional-Erweiterung kann später separat geplant werden.
</objective>
