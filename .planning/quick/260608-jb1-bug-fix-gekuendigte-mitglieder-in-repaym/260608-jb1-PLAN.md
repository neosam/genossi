<objective>
Fix den stillen Bug: gekuendigte Mitglieder erscheinen NICHT in der bereits offenen Repayment-Periode, obwohl die Phase fuer ihr fiscal_year existiert. Der bestehende Auto-Fill in `open_repayment_phase` laeuft NUR beim `Preparation -> Open`-State-Transition, nicht beim nachtraeglichen Kuendigen in eine bereits offene Phase. `partial_repayment` (Step 9+12) hat die korrekte Phase-Resolve+Entry-Create-Logik bereits — die wird hier symmetrisch in `cancel_membership` und in den Voll-Uebertrag-Branch von `transfer_shares` uebertragen.

Purpose: Konsistente Sichtbarkeit gekuendigter Mitglieder in der Repayment-Periode — egal welcher Pfad (Kuendigung, Voll-Uebertrag, Teil-Rueckgabe) die Member-Mutation ausloest und egal in welcher Reihenfolge Phase und Kuendigung passieren.

Output:
- `genossi_service_impl/src/membership_adjust.rs` mit zwei neuen Process-String-Konstanten und zwei symmetrischen Phase-Resolve+Entry-Create-Bloecken (gespiegelt aus `partial_repayment` Step 9+12).
- 5 neue E2E-Tests in `genossi_bin/tests/membership_adjust_e2e.rs`.

        let target_phase_existing = all_phases
            .iter()
            .find(|p| p.fiscal_year == effective_for_repayment.fiscal_year)
            .cloned();

        if let Some(ref existing) = target_phase_existing {

            }
        }

        let target_phase: RepaymentPhaseEntity = match target_phase_existing {
            Some(p) => p,
            None => {
                let share_value = all_phases
                    .first()
                    .map(|p| p.share_value)
                    .unwrap_or(DEFAULT_SHARE_VALUE_CENT);
                let auto_phase = RepaymentPhaseEntity {
                    id: self.uuid_service.new_v4().await,
                    fiscal_year: effective_for_repayment.fiscal_year,
                    share_value,
                    status: RepaymentPhaseStatus::Open,
                    opened_at: Some(created_pdt),
                    closed_at: None,
                    created: created_pdt,
                    deleted: None,
                    version: self.uuid_service.new_v4().await,
                };

                    self,
                    self.repayment_phase_dao,
                    &auto_phase,
                    REPAYMENT_PHASE_CREATE_PROCESS,
                    &user_id,
                    tx
                );
                auto_phase
            }
        };

        let existing_entries = self
            .repayment_entry_dao
            .find_by_member_and_phase(from_entity.id, target_phase.id, tx.clone())
            .await?;
        if existing_entries.is_empty() {
            let new_entry = RepaymentEntryEntity {
                id: self.uuid_service.new_v4().await,
                member_id: from_entity.id,
                phase_id: target_phase.id,
                // KRITISCH: shares (= from.current_shares VOR Decrement, garantiert
                // durch `will_become_zero`-Definition). NICHT from_final.current_shares!

                status: RepaymentEntryStatus::Open,
                created: created_pdt,
                deleted: None,
                version: self.uuid_service.new_v4().await,
            };
            crate::audited_create!(
                self,
                self.repayment_entry_dao,
                &new_entry,
                TRANSFER_FULL_REPAYMENT_PROCESS,
                &user_id,
                tx
            );
        }
    }
