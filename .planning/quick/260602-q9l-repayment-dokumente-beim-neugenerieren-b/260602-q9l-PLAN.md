<objective>
Make RepaymentLetter regeneration idempotent. When a Vorstand re-runs
`POST /api/repayment-phases/{id}/letters` for a recipient that already has a
RepaymentLetter for the same fiscal year, the existing MemberDocument row must
be **overwritten in place via `audited_update!`** instead of producing a
duplicate row via `audited_create!`. Audit hash-chain must remain valid; the
re-generation must produce UPDATE-class audit entries (not CREATE). The
on-disk PDF is overwritten transparently because we reuse the existing
`doc_id` (which the storage layer uses as `{doc_id}.pdf` filename).

Purpose: Closes the deferred TODO from `genossi_service/src/member_document.rs:95-100`
(option 1 — same-row update via audit macro). Stops the linear storage/UI growth
that Phase 13 WR-06 flagged. Keeps the audit trail of every regeneration in
the audit_log via `audited_update!`.

Output: Modified `genossi_service_impl/src/repayment_letter.rs` with a
find-then-update-or-create branch inside the write-tx loop, plus 2-3 new
unit tests covering: (a) first generate -> create, (b) second generate ->
update same row, (c) negative — no RepaymentEntryDao::update side-effect.
</objective>
