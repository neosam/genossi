<objective>
Inbox-Reply kann genau wie der Compose-Flow MemberDocuments + StaticDocuments aus der DB anhängen. KEIN lokaler File-Upload, KEIN multipart — Reply-Request bleibt JSON und nimmt nur IDs entgegen, die im Backend genau wie in `MailServiceImpl::create_job` (genossi_mail/src/service.rs:300-368) zu MailRecipientAttachment-Rows + MailJobStaticAttachment-Joins persistiert werden.

Purpose: Vorstand muss beim Beantworten von Inbound-Mails Belege/Anschreiben aus dem bestehenden Dokumenten-Bestand mitschicken können — bisher nur im Compose-Flow möglich. Vorheriger Versuch (Quick 260607-r96) hat fälschlich lokalen File-Upload via multipart implementiert und wurde verworfen — daher hier explizit: "das selbe wie beim Compose" = Picker auf existierenden Docs.

Output: Erweiterter `InboxService::reply`, erweiterter REST-Handler `reply_inbox`, neue shared Component `MailAttachmentPicker`, umgebautes Reply-Form mit eingebundenem Picker, erweiterte `api::reply_inbox_mail`-Signatur.
</objective>
