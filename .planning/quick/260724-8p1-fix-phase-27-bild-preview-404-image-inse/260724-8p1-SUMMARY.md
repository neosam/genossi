# Quick Task 260724-8p1 — Summary

## Was gemacht wurde

Der Phase-27-Bild-Preview-404 wurde behoben. `image_insert_html()` baute die
Preview-`<img src>` relativ (`/api/mail/assets/{id}/bytes`) und umging damit
`config.backend`. Auf `genossi-beta` (`config.backend` = `.../api`, echte
API-Calls laufen über `.../api/api/...` via Reverse-Proxy) landete die relative
URL auf einer nicht existierenden Backend-Route → 404.

**Fix:** `image_insert_html(backend: &str, id: &str)` baut die `src` jetzt
`{backend}/api/mail/assets/{id}/bytes` — identisch zur bewiesenermaßen
funktionierenden API-Basis, die alle anderen Requests verwenden.

## Geänderte Dateien

- `genossi-frontend/src/component/mail_compose/wysiwyg_toolbar.rs`
  - Signatur `image_insert_html(backend, id)`; `src` backend-basiert; Doc-Kommentar aktualisiert.
  - Toolbar-Button-Caller übergibt `&config.backend`.
  - Unit-Test angepasst + Regression-Guard `preview_src_uses_backend_base_not_relative` ergänzt.
- `genossi-frontend/src/component/mail_compose/wysiwyg_editor.rs`
  - Drag&Drop-Handler-Caller übergibt `&config.backend`.

## Verifikation

- `cargo test image_insert_html` → 2/2 grün (inkl. Regression-Guard).
- `cargo test wysiwyg` → 18/18 grün (Toolbar + Editor kompilieren, keine Regression).
- Der Regression-Test schlägt fehl, sobald die `src` wieder relativ (ohne `config.backend`) gebaut wird.

## Warum sicher

Die Preview-`src` ist reine Live-Editor-Konvenienz: der Sanitizer (27-02) strippt
`src` beim Speichern; nur `data-genossi-asset-id` persistiert, beim Versand wird
CID injiziert. Kein env-spezifischer Wert wird gespeichert oder versendet.

## Follow-up (2026-07-25): Drag&Drop-Fix

Nach Bestätigung, dass Toolbar-Insert funktioniert, wurde auch Test 2 (Drag&Drop)
angegangen. Symptom: `ondrop` feuerte gar nicht — kein Upload, kein `tracing`-Log,
kein Request.

**Root Cause:** `ondragover` cancelte nur via Dioxus-synthetischem
`evt.prevent_default()`. Das cancelt das native `dragover` in Dioxus 0.6 nicht
zuverlässig; ein Drop-Target feuert `ondrop` aber nur, wenn `dragover` (und in
manchen Browsern `dragenter`) auf dem nativen Event gecancelt wird.

**Fix (`wysiwyg_editor.rs`):** `ondragover` + neuer `ondragenter` cancellen auf dem
NATIVEN Event (`evt.downcast::<web_sys::Event>()` → `web_event.prevent_default()`,
derselbe Pfad wie der Drop-Handler). Drop-Handler zusätzlich nativ gehärtet.
Grep-Gate-Regression `dragover_cancels_on_native_event` ergänzt; `cargo test wysiwyg`
19/19 grün. Verifikation im echten Browser steht nach Frontend-Deploy noch aus
(echtes Datei-DnD ist nicht unit-testbar).
