# Quick Task 260724-8p1: Fix Phase-27 Bild-Preview-404

## Problem

Beim Einfügen eines Bildes über den WYSIWYG-Toolbar-Button (Phase 27) wird die
Datei korrekt hochgeladen (`POST {config.backend}/api/mail/assets` → 201 + Asset-ID,
Zeile persistiert), aber die anschließende Bild-Preview via
`GET /api/mail/assets/{id}/bytes` liefert auf `genossi-beta` **404 Not Found**;
das Bild erscheint nicht im Editor.

## Root Cause

`image_insert_html()` in `genossi-frontend/src/component/mail_compose/wysiwyg_toolbar.rs`
emittiert eine **relative** Preview-`src` (`/api/mail/assets/{id}/bytes`), die
`config.backend` umgeht. Alle funktionierenden API-Calls bauen dagegen
`format!("{}/api/...", config.backend)`. Auf beta ist
`config.backend = "https://genossi-beta.nebenan-unverpackt.de/api"`, d.h. die echten
API-Calls laufen über `.../api/api/...` (der Reverse-Proxy mappt das auf den
Backend-Router). Die relative Preview-URL (`.../api/mail/assets/...`, einfaches
`/api`) landet dadurch auf einer Route, die der Proxy auf eine nicht existierende
Backend-Route abbildet → 404.

Belege (curl gegen beta, unauth): `.../api/api/mail/assets/{id}/bytes` → 401
(Route existiert), `.../api/mail/assets/{id}/bytes` → authentifiziert 404
(EntityNotFound-Mapping). Backend-Code ist korrekt (e2e-Roundtrip-Test
`test_mail_asset_upload_and_bytes_roundtrip` grün). Der Sanitizer strippt die
`src` beim Speichern ohnehin (nur `data-genossi-asset-id` persistiert; beim
Versand → CID), daher ist die `src` reine Live-Editor-Preview.

## Fix

`image_insert_html` baut die Preview-`src` **genauso** wie jeder andere API-Call —
über `config.backend`:

```rust
pub(crate) fn image_insert_html(backend: &str, id: &str) -> String {
    format!(r#"<img data-genossi-asset-id="{id}" src="{backend}/api/mail/assets/{id}/bytes">"#)
}
```

Damit ist die Preview-URL in JEDER Umgebung identisch zur bewiesenermaßen
funktionierenden API-Basis (dev: `http://localhost:8080/api/...`, beta:
`.../api/api/...`).
